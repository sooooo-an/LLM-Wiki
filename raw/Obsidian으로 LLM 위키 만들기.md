
## AS-IS

- 위키 유지 관리의 어려움
    - 문서 최신 상태 유지
    - 중복/불일치 데이터 정리
    - 링크 깨짐 수정
    - 구조 정리
    - 포맷 통일, 스타일 맞추기
- 대부분 LLM 문서 활용 방식: **RAG(Retrieval-Augmented Generation)** 방식 ⇒ 질문할 때마다 외부 문서를 검색해서 임시로 답을 만듦(on-demand)

```tsx
// RAG 방식
1. 문서 업로드
2. 문서 chunking (쪼개기)
3. 각 chunk → 임베딩 생성
4. Vector DB에 저장

[질문 시]
5. 질문 → 임베딩
6. Vector DB에서 유사 chunk 검색
7. (질문 + chunk) → LLM 입력
8. LLM이 답변 생성
```

1. Retrieval(검색)
    - 질문(query)을 벡터로 전환
    - 문서 DB(백터 DB)에서 유사한 텍스트 조각(chunk)을 검색
2. Generation(생성)
    - 검색된 chunk들을 LLM에 함께 넣어서
    - 그 내용을 근거로 답변 생성

## LLM Wiki란?

- 적용분야
    - 개인: 목표, 건강, 심리, 자기개발 추적 - 저널, 기사, 팟캐스트 노트를 모아 구조화된 자아 기록 구축
    - 연구: 수주~수개월에 걸쳐 논문, 기사, 보고서를 읽으며 진화하는 테제를 담은 포괄적 위치 구축
    - 독서: 챕터별로 정리하며 등장인물, 테마, 플롯 실을 페이지로 구성
    - 비즈니스/팀: 슬렉 스레드, 미팅 전사, 프로젝트 문서, 고객 통화로 LLM이 유지, 관리하는 내부 위키 구성 가능
- 아키텍처(3개 레이어)
    - 원문 소스(Raw sources): 큐레이션된 소스 문서 컬렉션 - 기사, 논문, 이미지, 데이터 파일
        - 변경 불가(immutable), LLM은 읽기만 하고 수정하지 않음
        - 이 레이어가 진실의 원천(source of truth)
    - 위키(The wiki): LLM이 생성하는 마크다운 파일 디렉터리 - 요약, 엔티티 페이지, 개념 페이지, 비교, 개요, 합성
        - LLM이 이 레이어를 완전히 소유: 페이지 생성, 소스 추가 시 업데이트, 교차 참조 유지
        - 사용자는 읽기만 하고, LLM이 작성
    - 스키마(The schema): LLM에게 위키 구조, 컨벤션, 워크플로를 알려주는 설정 문서 (Claude Code의 경우, `CLAUDE.md`)
        - LLM을 일반 챗봇이 아닌 체계적인 위키 관리자로 만드는 핵심 설정 파일
        - 사용자와 LLM이 시간이 지남에 따라 함께 진화시킴
- 주요 작업(Operations)
    - 인제스트(Ingest): 새 소스를 원문 컬렉션에 추가하고 LLM에게 처리를 지시
        - 새 소스 추가 → 핵심 내용 추출 → 요약 페이지 작성 → 관련 엔티티/개념 페이지 수정 → 인덱스 업데이트 → 변경 로그 기록
    - 쿼리(query): 질문하면 LLM이 원문 전체를 매번 검색하는 것보다, 이미 정리된 위키를 중심으로 답변함
        - 질문 → 관련 위키 페이지 확인 → 필요한 경우 원문 확인 → 답변/표/문서/슬라이드/차트 생성 → 좋은 결과는 위키에 다시 저장
    - 린트(Lint): 주기적으로 LLM에게 위키 상태 점검 요청
        - 검사 대상: 서로 모순되는 페이지, 최신 자료로 대체된 오래된 주장, 링크가 없는 고아 페이지, 중요한데 별도 페이지가 없는 개념, 누락된 교차 참조, 추가 조사가 필요한 빈틈
- 인덱싱 및 로깅
    - `index.md`: 위키의 수동/텍스트 기반 검색 인덱스(길잡이 지도 역할)
        - 질문 → [index.md](http://index.md) 먼저 읽음 → 관련 페이지 후보 찾음 → 해당 페이지 읽음 → 답변 생성
    - `log.md`: 시간순 기록 - 인제스트, 쿼리, 린트 통과 내역을 순서대로 기록
        - 각 항목의 접두사를 일관되게 작성하면 Unix 도구로 파싱 가능
- 팁 및 도구 활용법
    - Obsidian Web Clipper: 웹 기사를 마크다운으로 변환
    - 로컬 이미지 저장: Obsidian Settings → Files and links에서 첨부 폴더 경로 설정 후 단축키로 이미지를 로컬 디스크에 저장
    - Obsidian 그래프 뷰: 위키 전체 형태 파악
    - Marp: 마크다운 기반 슬라이드 덱 포맷
    - Dataview: 페이지 프론트매터를 대상으로 쿼리를 실행하는 Obsidian 플러그인
    - 위키는 마크다운 파일의 git 저장소

## LLM Wiki 만들기

1. Obsidian 설치하기
2. [https://ollama.com/](https://ollama.com/) 설치하기
3. [https://github.com/kytmanov/obsidian-llm-wiki-local](https://github.com/kytmanov/obsidian-llm-wiki-local) 설치하기
4. Ollama에서 모델 설치하기
5. 명령어를 이용하여 wiki 설정해주기
6. 작성된 초안을 raw에 올리기 
7. olw run을 통해 wiki 생성하기
    1. olw ingest —all 
    2. olw comile 
8. wiki/.drafts/: LLM이 만든 초안. 검토 대기 
9. olw review (approve/reject/edit)
10. wiki/: 승인된 위키 본문
11. 사람이 “정식 노트 가치가 있다”고 판단하면 해당 템플릿 적용해서 정리하기
12. 정식 노트로 들어가면 LLM이 안건들임
